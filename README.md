# pwcheck

查一个密码是否出现在**公开泄露库**里——但密码本身**永远不出本机**。

原理叫 k-anonymity（HaveIBeenPwned 的公开 API）：

1. 本地算密码的 SHA-1；
2. 只把前 **5 个十六进制字符**发给 `api.pwnedpasswords.com/range/<前缀>`；
3. API 返回所有同前缀的哈希后缀（约几百条），在**本地**比对计数。

完整哈希从不离开你的机器，服务端只知道"有人在查某个 5 字符前缀"，对应约 2^20 个可能的密码。

## 安装

零依赖，Python 3.10+：

```bash
python3 -m pwcheck        # 交互式输入（不回显）
```

## 用法

```bash
$ python3 -m pwcheck
请输入要检查的密码（不会显示）：
⚠️  该密码在已知泄露中出现 3864334 次，请立即更换。
```

```bash
python3 -m pwcheck --json      # {"leaked": true, "count": 3864334}
python3 -m pwcheck --timeout 10
```

退出码：`0` 未泄露 / `1` 已泄露 / `2` 出错（没输入、连不上 API 等）。

## 安全设计（为什么这么定）

- **密码只走交互式输入**（`getpass`，不回显）。故意**不提供** `--file` / 命令行参数传密码：
  命令行参数会进 shell 历史、`ps` 输出、审计日志——密码一旦出现在那里就洗不干净了。
- 管道喂入（`echo xxx | pwcheck`）**仅限测试用**，README 和帮助里都这么写；生产环境请手输。
- 用完后尽快覆盖内存中的明文变量（CPython 不保证清零，但至少不长期持有引用）。

## 诚实说明（必读）

- **只查公开泄露语料**：HaveIBeenPwned 收录的是已公开的泄露库。**"未出现" ≠ 密码够强**——
  `Password123!` 这类弱密码可能还没进泄露库，但依然几秒可破。强度问题请用兄弟项目 `passgen` 生成高熵密码。
- **SHA-1 说明**：这里用 SHA-1 不是因为它"安全"，而是因为 HIBP 的 API 约定就是 SHA-1 前缀。
  我们只用它做**查找键**，不做任何认证或签名；碰撞攻击对这个场景没有意义（攻击者要的是反查你的密码，
  而他拿到的只有 5 个字符的前缀）。
- API 有速率限制，频繁查询会被 429；此时工具会报"API 返回 HTTP 429"。
- 需要联网；公司网/TLS 中间人环境下看到的是代理行为，属环境限制。
